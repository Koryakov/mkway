## 1. Goal

«It seems should have the rules for the process. And fix it.» - owner, 2026-11-17. Git names every file from the TOP of the repository. With a task root below the top, the engine read those names as if they were root-relative, so a file of the top was judged under the made-up in-root name of the same text: it passed when that name met a card Path, an exempt entry, the session's own writable set or an open card with no Paths, and a top `.claude/settings.json` was judged as the task's own closed lock target. One helper, `helpers.from_top(name, root, prefix)`, reads a git name against the top: the root-relative name for a file under the root, a distinct `Outside` value for any other (whole segments, case-folded on Windows, a name that cannot be placed is outside). Every reader of git's names uses it. A commit that takes an outside file is refused with the new reason `file-outside-root`; the lock gate never matches an outside file against a lock target; the start line, `mkway check` and the board show it as `outside the task root: <name>`; `mkway rules` reads its tree with the top-relative path. With the root at the top nothing changes. Each `git diff` that prints file names pins its name form (`-c diff.relative=false`, R360), so a git setting `diff.relative=true` cannot hide an outside file or an in-root file outside the current folder. The «outside files in a card» feature is not built (R358 1).

Cut forecast (R358): BEHAVIOUR CHANGE of the commit gate (R360): it reads git's names as UTF-8 bytes; before, on Windows, a non-ASCII name was decoded with the locale code page (a wrong name, so its card-Path, ignore and size checks looked at another file); the commit-tests gate keeps the locale text. A commit that passed only through the defect is refused after the fix: an outside file whose made-up name equalled an allowed in-root path no longer passes. The owner's `paths.outside_writable` entry stays valid for writes; the commit of such a file is refused `file-outside-root` until the feature exists. R359 measured on one real task's history that no commit touched a file outside its root, so the fix refuses nothing that work does today. Open Paths entries that match only through the defect: none, checked by the operator on a real task's register (see the Log line of R359 E).
