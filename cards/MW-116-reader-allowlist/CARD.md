## 1. Goal

«we should have straight, simple as its possible mkway process - it should help work on tasks - not be as evil dog - it should be strong helper!» — owner, 2026-11-16 (R263). Order: ruling R272 (G2) with R287, R287c and R287d. Concept line 1, kind K3: the reader that judges a test is told which files to read, but no engine code enforced it. The engine now ships the reader agent with a frontmatter PreToolUse hook (`engine/reader_hook.py`); `mkway reader start <card>` writes the allow file of the spawning session (the test files of the card's nodes and an engine-written extract of the Acceptance rows of the named nodes, never the card file); the hook lets Read and Grep pass on listed files only (and the handback), refuses every other path and tool, and writes one record row per call with the decision; the end of the run empties the list; `verdict add` refuses `verdict-reader-unguarded` for a run with no record row. Help it gives the task: the reader is held to its two inputs without anyone watching, and a verdict from an unguarded run never counts. Scope: the hook guards the test checker only; a reader of outbox texts is out of scope. The hook runs only after the workspace trust dialog for the agent file's folder (sub-agents.md:785-787): the way out is to trust the folder and run the reader again.
