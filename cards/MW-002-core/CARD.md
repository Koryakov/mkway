### Known limits

- Only a gate that runs a subprocess (tests) can be stopped at its budget; an in-process gate relies on being fast, and the platform timeout is its backstop.
- The interpreter check (C34, E59, E66) runs the program and reads its answer: a program made to print a Python version, such as `(3, 9)`, passes it, and on Windows a bare name is looked up in the task root first. It stops mistakes, not a deliberate fake; install is owner-only, and MW-003 locks `<state.dir>/` and the settings file (fix check 3 L6).
- `tools/term_scan_allow.txt` is protected by review only in the engine repository: one commit can add a marker and its row together, and every check stays green. Every checker runs `git diff <base>..<head> -- tools/term_scan_allow.txt` and `git diff <base>..<head> -G "term-scan: allow"`; a non-empty result needs the order's word. This holds until the engine runs its own gates and its profile names the list in `locks.targets[]` (fix check 4 F2).
- The probe's stop on Windows uses a job object that the probe joins right after it starts; a process it starts in that first instant, before it joins, is not reached. If the job cannot be made, `taskkill /T` is used, which does not reach a grandchild whose parent already exited (fix check 4 F5).
