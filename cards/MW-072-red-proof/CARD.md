`migration`) declares a card whose new tests may pin behaviour that already holds; any other card has none.

## 1. Goal

A tests-only commit is run, and each new test id must fail (red by missing module when the module lies in the card's own
Paths); the red ids are recorded in the root's state by card. A code commit needs every recorded id to pass (a deleted,
renamed or skipped one counts as still red) and a record in this root. A commit that adds a new test id together with code
is refused unless the id is in the red record or is a declared pinning id. Ruling R183: in a red commit a new id that
passes is allowed when its docstring starts `Checks:` and the commit holds a red id; every `Catches:` id must be red. —
ruling R177, gaps 1 and 2; plan gates G2, G2b,
G4, G4b; gate key `tests.red_proof`, mode trip (default) or watch.

Real case to replay: `engine/gate_commit_tests.py` line 354 `return gate.allow()  # the red-first commit: tests alone may
be red` let a tests-only commit through with no run, and a commit of a test together with its code passed when the test
was green (test-after).
