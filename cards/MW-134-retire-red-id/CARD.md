## 1. Goal

A card's red record is the union of all its red rows in HEAD's history, and nothing removes an id. When a requirement changes after the red commit, no code commit of that card can pass: the recorded id is gone and `red-ids-still-red` refuses. Now an explicit, recorded way out: a valid `case_map.md` line of the card (a rename or a drop) retires the left id, in a tests-only (or documents-only) commit whose message names a decision of the ledger that another session wrote. Nothing is inferred from a missing test; a present id that fails is never retired; a line staged in a code commit retires nothing. Each retirement is one record row and one inbox notice to the orderer. The default of `tests.red_proof.decision_pattern` is one place (a root with a ledger and no key reads the ledger's id form). Basis: rulings R347, R348, R348a.
