### Known limits

- `shell_writes` is best effort (decided): a program it does not know, a `python script.py`, or a copy of the engine's command line under another name is not seen. The backstop for anything that reaches git is `lock-closed-commit`; `engine/`, `locks/` and `state/` are git-ignored, so there it is not.
- Two coordinated undetected writes (the register and `register.sha`) defeat the seal (decided limit); the register's row diff in git is the backstop.
- C44 (R23): `CLAUDECODE` is seen, not documented; inside a hook its absence is warned `session-signal-missing` (E30). `mkway.py` refuses every owner-only command when it is present, any value (E66). A session can strip the variable (`env -u CLAUDECODE`, `unset`), so this layer is a tripwire that teaches the route, not a wall; the wall is the OS permission on the lock state, the profile and the install record (owner).
- A chain or pipe with an engine call is refused: run the mkway command alone, in its plain form (H4).
- The shell gate reads the command text only: a script file that runs an owner-only mkway command is not read by it, as a Python file is not for the lock gate (R43); the CLI's own refusal (E66) then applies.
- A lock-target path built without its literal is not seen (R43, list items 5 and 6): a write the lock gate cannot read is refused only when the command names a closed target literally, else logged `write-target-unresolved`. A glob write whose literal folder lies inside a closed target refuses (E67); any other glob write is allowed, not logged. Backstop until MW-021: the tracked targets (profile, register, bundle `.gitignore` and `.gitattributes`, `mkway.lock`) have the commit check (`lock-closed-commit`, at commit time only); `engine/`, `locks/`, the state folder and `.claude/settings.local.json` are git-ignored and have no commit check: only the owner's review and the OS permissions remain.
- Item 18 (A-M1 remainder): nothing left; item 8 (E73) built `allow_abbrev=False` on every parser and the gate's prefix refusal.
- The git time limit is 10 s per git call, not per gate; one commit check can make up to six calls (B3; close-fix item 19, not built).
- A commit inside another program is not read (E68): with `vcs: git` a carrier whose argument text names `git … commit` is refused `command-unparsed` (the form is in E68); a commit started from a script file is not seen.
- The register is one shared file: a register commit carries every engine-written row change since the last one, whoever made it.
